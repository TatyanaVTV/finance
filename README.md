# Финансовый мониторинг

Веб-приложение для учёта доходов и расходов, генерации отчётов (PDF, Excel) и аналитики.  
Реализовано на **Java 21**, **Spring Boot 3.5.3**, **PostgreSQL** (`dev`/`prod`) и **H2** (тесты).

## Стек технологий

- **Backend:** Spring Boot, Spring MVC, Spring Data JPA, Hibernate, Spring Security (Basic Auth)
- **Frontend:** Thymeleaf, Bootstrap 5, Chart.js, чистый JavaScript (без jQuery)
- **База данных:** PostgreSQL (`dev`/`prod`), H2 (тесты)
- **Сборка:** Gradle (Kotlin DSL)
- **Маппинг:** MapStruct
- **Экспорт отчётов:** iText (PDF), Apache POI (Excel)
- **Логирование:** SLF4J + Lombok
- **Тесты:** JUnit 5, Mockito, AssertJ, Spring Boot Test, MockMvc

## Запуск приложения

### Требования
- **JDK 21+**
- **PostgreSQL** (локально или через Docker)
- **Gradle** (или используйте встроенный wrapper)

### Настройка базы данных (dev)
Создайте базу `finance_db` с пользователем `admin` / паролем `admin`:
```sql
CREATE DATABASE finance_db;
```
Или используйте `docker-compose.yml` (прилагается).

### Сборка и запуск
```bash
./gradlew clean build
java -jar build/libs/finance-*.jar --spring.profiles.active=dev
```
Или через IDE с параметром `-Dspring.profiles.active=dev`.

При первом запуске (`dev`) автоматически создаются:
- пользователь `test@example.com` / `password`
- дефолтные категории (доходы/расходы)
- 30 тестовых транзакций за последние 6 месяцев

## Доступные профили
| Профиль | База данных | Описание |
|---------|-------------|----------|
| `dev`   | PostgreSQL  | Режим разработки, `ddl-auto=create-drop`, тестовые данные |
| `test`  | H2 (mem)    | Запуск тестов, `ddl-auto=create-drop` |
| `prod`  | PostgreSQL  | Продакшен, `ddl-auto=validate`, CSRF включён |

## Основные возможности

- **Регистрация / аутентификация** (Spring Security, Basic Auth)
- **Дашборд** – ключевые метрики (доходы, расходы, баланс) и график за текущий месяц
- **Управление транзакциями** – создание, редактирование (inline), удаление
- **Категории** – раздельные списки для доходов и расходов, создание/удаление/редактирование
- **Отчёты** – выбор периода (месяц/квартал/год), экспорт в PDF и Excel, корректные имена файлов
- **Профиль** – редактирование имени и email
- **Адаптивный интерфейс** – Bootstrap 5, работает на мобильных устройствах

## Экспорт отчётов

- **PDF** – шрифт Merriweather, поддержка кириллицы, таблица с транзакциями, итоги
- **Excel** – автоподбор ширины столбцов, даты с временем

## REST API (примеры)

| Метод | URL | Описание                                                     |
|-------|-----|--------------------------------------------------------------|
| GET | `/api/transactions` | Список транзакций (параметры `from`, `to`)                   |
| POST | `/api/transactions` | Создание транзакции (JSON)                                   |
| PUT | `/api/transactions/{id}` | Обновление транзакции                                        |

## Важные особенности

- Все исключения обрабатываются централизованно (`GlobalExceptionHandler` для MVC, `RestExceptionHandler` для REST)
- Валидация на стороне сервера + клиентские подсказки
- Логирование на английском, сообщения исключений – на русском
- Идентификаторы – UUID (автогенерация через Hibernate)
- Мапперы реализованы с помощью `MapStruct` с `componentModel = "spring"`
- **Lombok** активно используется для сокращения шаблонного кода: `@Data`, `@Builder`, `@RequiredArgsConstructor`, `@Slf4j` и другие аннотации применяются в сущностях, DTO, сервисах и контроллерах
- Фабричные методы для создания исключений
- **JavaScript-скрипты**:
    * Все скрипты вынесены в отдельные файлы (каждый для своей страницы)
    * Используется чистый JavaScript без jQuery, но с Bootstrap JS для работы адаптивного меню (гамбургер)
    * Для подстраховки написан собственный резервный скрипт `menu.js`, который переключает меню вручную, если Bootstrap JS не загрузился
    * Работа с REST API через `fetch` с обработкой ошибок
    * Динамическое обновление интерфейса (inline-редактирование, фильтрация категорий при смене типа транзакции)
    * Генерация отчётов через `fetch` с получением бинарных данных (blob) и автоматическим скачиванием

## Разработка и поддержка

- Код соответствует принципам **DRY**, **SOLID**, **Inversion of Control**
- Для форматирования дат в интерфейсе используется единый формат `dd.MM.yyyy HH:mm`
- В репозиториях – методы с сортировкой по дате (новые транзакции будут отображаться вверху списка)
- Для ускорения разработки подключён **Lombok**, **MapStruct**
